# Implementation Plan: F2.1 — Active Game Configuration (Multi-Variant)

**Spec:** [f2.1-active-game-configuration.md](../../spec/game-core/f2.1-active-game-configuration.md)
**Epic plan:** [_epic-E2-game-core.md](./_epic-E2-game-core.md)

---

## 1. Overview

Currently, `campaigns.game_variant` is a single TEXT column — one campaign = one game variant. The spec now requires a campaign to support **multiple active game variants**, with the backend randomly selecting one per request.

**Approach:** Change `campaigns.game_variant` from `TEXT` to `TEXT[]` (PostgreSQL array). All variants in the array are considered active. No new table needed.

| Layer | Current | Target |
|---|---|---|
| DB | `campaigns.game_variant TEXT` | `campaigns.game_variants TEXT[]` |
| Backend service | `getActiveConfig()` returns single variant | Reads array, randomly selects one |
| API response | `{ campaignId, gameVariant }` | Same shape — frontend unchanged |
| Frontend | Renders the variant from API response | No change needed |

**Frontend impact: zero.** The API response shape stays the same.

## 3. Campaign Service Update

### File: `game-api/services/campaign.service.js`

```javascript
'use strict'

function createCampaignService(knex) {
  async function getActiveConfig() {
    const campaign = await knex('campaigns').where({ is_active: true }).first()
    if (!campaign) return null

    const variants = campaign.game_variants
    if (!variants || variants.length === 0) return null

    // Uniform random selection
    const selected = variants[Math.floor(Math.random() * variants.length)]

    return {
      campaignId: campaign.id,
      gameVariant: selected,
      winProbability: Number(campaign.win_probability),
    }
  }

  async function getRandomCoupon(campaignId) {
    // unchanged — coupon pool is shared across all variants
    const now = new Date().toISOString()
    const coupons = await knex('campaign_coupons')
      .where({ campaign_id: campaignId })
      .where('end_date', '>', now)
      .where('start_date', '<=', now)

    if (coupons.length === 0) return null

    const totalWeight = coupons.reduce((sum, c) => sum + c.weight, 0)
    let random = Math.random() * totalWeight

    for (const coupon of coupons) {
      random -= coupon.weight
      if (random <= 0) return coupon
    }

    return coupons[coupons.length - 1]
  }

  return { getActiveConfig, getRandomCoupon }
}

module.exports = { createCampaignService }
```

**Key change:** Read `campaign.game_variants` (array) → random pick one. Return shape unchanged.

### Step 5 — Manage variants via SQL

```sql
-- Add flip-card to active variants
UPDATE campaigns
SET game_variants = array_append(game_variants, 'flip-card')
WHERE id = 'default-campaign';

-- Remove flip-card (only scratch-card remains)
UPDATE campaigns
SET game_variants = array_remove(game_variants, 'flip-card')
WHERE id = 'default-campaign';

-- Set exactly one variant
UPDATE campaigns
SET game_variants = ARRAY['scratch-card']
WHERE id = 'default-campaign';

-- Set multiple variants
UPDATE campaigns
SET game_variants = ARRAY['scratch-card', 'flip-card']
WHERE id = 'default-campaign';
```

## 9. Acceptance Criteria Mapping

| AC | How it's met |
|---|---|
| AC-201 | Frontend calls `GET /game/config` on every WebView load (unchanged) |
| AC-202 | API returns `gameVariant: "scratch-card"` → frontend renders Scratch Card (unchanged) |
| AC-203 | API returns `gameVariant: "flip-card"` → frontend renders Flip Card (unchanged) |
| AC-204 | Operator sets `game_variants = ARRAY['flip-card']` → API only returns flip-card |
| AC-210 | `game_variants = ARRAY['scratch-card','flip-card']` → random pick → different results per request |
| AC-211 | `getActiveConfig()` returns single object, not array |
| AC-212 | `array_remove(game_variants, 'scratch-card')` → never returned |
| AC-213 | `game_variants = ARRAY[]::TEXT[]` or no active campaign → returns null → API 404 |

## 10. Risk & Rollback

| Risk | Mitigation |
|---|---|
| Migration drops `game_variant` column | `exports.down` recreates column from `game_variants[1]` |
| Empty array in DB | Service checks `variants.length === 0` → returns null → API 404 |
| Unrecognized variant in array | Frontend rejects unknown variant → shows error screen (VAL-201) |
| Knex array handling | Knex/pg driver natively supports PostgreSQL `TEXT[]` — reads as JS array, writes via `JSON.stringify()` or raw SQL |
