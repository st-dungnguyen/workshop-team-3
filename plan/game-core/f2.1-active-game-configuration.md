## 1. Responsibility

F2.1 is a config file + a type-safe registry. It declares which variant is active at deploy time. All consumers (the game shell, variant renderer) read from it — nothing reads `VITE_GAME_VARIANT` directly except this file.

## 3. Game Config File

### File: `src/config/game.config.ts`

```typescript
import type { GameConfig, GameVariant } from '@app/shared/models/game';

const KNOWN_VARIANTS: GameVariant[] = ['scratch-card', 'flip-card'];

const rawVariant = import.meta.env.VITE_GAME_VARIANT ?? 'scratch-card';

if (!KNOWN_VARIANTS.includes(rawVariant as GameVariant)) {
  throw new Error(
    `[game.config] Unknown game variant: "${rawVariant}". ` +
    `Valid options: ${KNOWN_VARIANTS.join(', ')}`
  );
}

export const GAME_CONFIG: GameConfig = {
  activeVariant: rawVariant as GameVariant,
  campaignId: import.meta.env.VITE_CAMPAIGN_ID ?? '',
};
```

The `throw` at module level satisfies REQ-204 — the app fails loudly with a readable message rather than silently rendering nothing.

## 4. Env Variables

Add to `src/vite-env.d.ts`:

```typescript
interface ImportMetaEnv {
  readonly VITE_DEMO_MODE: string;
  readonly VITE_GAME_VARIANT: string;
  readonly VITE_CAMPAIGN_ID: string;
}
```

Set in `.env` (or per-environment):
```
VITE_GAME_VARIANT=scratch-card
VITE_CAMPAIGN_ID=campaign-2026-summer
```

To switch to Flip Card for next season: change `VITE_GAME_VARIANT=flip-card`, redeploy. Zero native app changes required (satisfies CON-201, AC-204).

## 5. Acceptance Criteria Mapping

| AC | How it's met |
|---|---|
| AC-201 | `VITE_GAME_VARIANT=scratch-card` → `GAME_CONFIG.activeVariant === 'scratch-card'` → `VariantRenderer` renders `ScratchCard` only |
| AC-202 | `VITE_GAME_VARIANT=flip-card` → `VariantRenderer` renders `FlipCard` only |
| AC-203 | Unknown variant → `throw` at module load → React error boundary catches and renders a clear error |
| AC-204 | Change env var + redeploy → new variant loads; native app URL unchanged |
