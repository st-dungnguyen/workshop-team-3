## Implementation

AppLink navigation is handled directly inside `WinResult` in `GameResult.tsx`. In the single-call design, the `couponId` is already available in props when the result screen renders — no additional API call is needed before navigating.

### File

`src/app/pages/game/containers/GameResult.tsx` — `WinResult` sub-component

### CTA handlers — Actual Implementation

```typescript
// WinResult in GameResult.tsx
const handleUseCoupon = () => {
  if (!coupon?.id) return;  // guard for missing couponId
  const encodedId = encodeURIComponent(coupon.id);
  window.location.href = `${COUPON_BASE_URL}/app/coupon/detail?id=${encodedId}`;
};

const handleMyCoupon = () => {
  window.location.href = `${COUPON_BASE_URL}/app/main?to=coupon_list`;
};
```

`COUPON_BASE_URL = import.meta.env.VITE_SKYLARK_BASE_URL ?? 'https://www.skylark.co.jp'`

No loading state — navigation fires synchronously on tap. The background claim has already fired in `useGameSession.handlePlayInitiated()`.

### AppLink URLs — Actual

| CTA | i18n key | URL |
|---|---|---|
| "Use Coupon" | `result.useCoupon` | `${COUPON_BASE_URL}/app/coupon/detail?id={encodedId}` |
| "My Coupon" | `result.myCoupon` | `${COUPON_BASE_URL}/app/main?to=coupon_list` |

> **Spec vs. implementation:** The spec (F3.2) documents `/app/coupon/segment?id=` and `/app/coupon`, but the implemented URLs are `/app/coupon/detail?id=` and `/app/main?to=coupon_list`. The spec should be updated when AppLink targets are formally confirmed with the native team.
