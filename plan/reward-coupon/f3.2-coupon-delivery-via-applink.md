## Implementation

AppLink navigation is handled directly inside `WinResult` in `GameResult.tsx`. In the single-call design, the `couponId` is already available in props when the result screen renders — no additional API call is needed before navigating.

### File

`src/app/pages/game/containers/GameResult.tsx` — `WinResult` sub-component

### CTA handler

```typescript
const handleCta = async (intent: 'claim' | 'useNow') => {
  if (ctaState === 'loading') return;  // double-tap guard (CON-301)
  setCtaState('loading');
  try {
    if (coupon) {
      const encodedId = encodeURIComponent(coupon.id);  // SEC-322
      if (intent === 'useNow') {
        window.location.href = `${COUPON_BASE_URL}/app/takeout?coupon_id=${encodedId}`;
      } else {
        window.location.href = `${COUPON_BASE_URL}/app/coupon/segment?id=${encodedId}`;
      }
    }
  } catch {
    setCtaState('error');
  }
};
```

`COUPON_BASE_URL` comes from `import.meta.env.VITE_SKYLARK_BASE_URL ?? 'https://www.skylark.co.jp'`.

### AppLink URLs

| Intent | URL |
|---|---|
| `claim` | `/app/coupon/segment?id={encodedId}` |
| `useNow` | `/app/takeout?coupon_id={encodedId}` |

`/app/takeout` requires Skylark app v8.0.7+. Confirm target app version covers this before launch.

### Spec deviations

- **REQ-325 / GUD-321**: No transition message between `rewarded` and AppLink — navigation fires on CTA tap. A brief "クーポンを獲得しました！" message is out of scope until confirmed needed by UX.
- **REQ-326 guard**: If `coupon` is null, no navigation fires and `ctaState` goes to `'error'` (catch block handles it since `handleCta` doesn't navigate when coupon is null — but currently doesn't set error explicitly; guarded by `if (coupon)` branch simply not navigating, leaving `ctaState === 'loading'`). This is a minor UX gap — if coupon is null, CTAs stay in loading state indefinitely. Acceptable for now since the play API always returns coupon when outcome is win.
