# Implementation Plan: F1.2 — JS Bridge Token Reception

**Spec:** [f1.2-js-bridge-token.md](../../spec/auth-bridge/f1.2-js-bridge-token.md)
**Epic plan:** [_epic-E1-auth-bridge.md](./_epic-E1-auth-bridge.md)

---

## 1. Responsibility

F1.2 is the second extraction method in `AuthBridgeService`. It registers a `window` message listener that stays active for the session. When a valid `AUTH_TOKEN` message arrives, it passes the token to the validation flow — but only if the URL param channel has not already claimed the "first wins" slot.

---

## 2. Message Contract

```typescript
// Expected inbound message shape
interface BridgeMessage {
  type: 'AUTH_TOKEN';
  token: string;
}
```

Any message where `type !== 'AUTH_TOKEN'` is silently ignored.  
Any message where `token` is absent, empty, or whitespace-only is discarded.

---

## 3. Implementation

### File: `src/app/core/auth/services/auth-bridge.service.ts`

```typescript
extractFromBridgeMessage(event: MessageEvent): string | null {
  let payload: unknown;
  try {
    payload = typeof event.data === 'string' ? JSON.parse(event.data) : event.data;
  } catch {
    return null; // malformed JSON — discard
  }

  if (
    typeof payload !== 'object' ||
    payload === null ||
    (payload as Record<string, unknown>).type !== 'AUTH_TOKEN'
  ) {
    return null; // wrong type or malformed — silently ignore (REQ-203)
  }

  const token = (payload as Record<string, unknown>).token;
  if (typeof token !== 'string' || token.trim().length === 0) {
    return null; // missing or empty token (REQ-204, VAL-201)
  }

  return token;
}
```

### File: `src/app/core/auth/hooks/useAuthBridge.ts`

```typescript
useEffect(() => {
  const urlToken = authBridgeService.extractFromUrlParam();
  if (urlToken) {
    tokenReceivedRef.current = true;
    handleValidate(urlToken);
    return;
  }

  const handleMessage = (event: MessageEvent) => {
    if (tokenReceivedRef.current) return; // first-wins lock (CON-201)
    const bridgeToken = authBridgeService.extractFromBridgeMessage(event);
    if (bridgeToken) {
      tokenReceivedRef.current = true;
      handleValidate(bridgeToken);
    }
  };

  window.addEventListener('message', handleMessage);
  return () => window.removeEventListener('message', handleMessage); // cleanup on unmount
}, [retryCount]); // retryCount re-registers listener on manual retry
```

The listener is registered synchronously in `useEffect` — it is active before the first paint, so bridge messages sent immediately after load are not missed (satisfies AC-205, GUD-201).

---

## 4. Race Condition: Bridge message before URL param processed

In practice this cannot happen because `extractFromUrlParam()` is synchronous and runs first in the same effect. But if it could, `tokenReceivedRef` prevents double-processing.

---

## 5. Acceptance Criteria Mapping

| AC | How it's met |
|---|---|
| AC-201 | `extractFromBridgeMessage()` validates the shape; `handleValidate()` is called |
| AC-202 | `type !== 'AUTH_TOKEN'` → returns `null` → `handleMessage` does nothing |
| AC-203 | Empty token check → returns `null` |
| AC-204 | `tokenReceivedRef.current` check at top of `handleMessage` — subsequent bridge messages are skipped |
| AC-205 | Listener registered synchronously in `useEffect` before any async operations |

---

## 6. Security Notes

- `event.data` is parsed defensively — `try/catch` on JSON.parse (satisfies SEC-201).
- No logging of token value inside `extractFromBridgeMessage` (satisfies SEC-202).
- No write to any storage (satisfies SEC-203).
