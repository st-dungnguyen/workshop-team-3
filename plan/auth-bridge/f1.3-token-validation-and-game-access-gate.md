## 1. Responsibility

F1.3 owns everything after a token is received: calling the backend, branching on the result, and rendering the appropriate UI state. It is the enforcement point — no game screen is ever rendered with an unvalidated token.

## 2. Auth Context — Modified Shape

### File: `src/app/shared/contexts/auth.context.tsx`

Replace the current context shape entirely:

```typescript
export type AuthStatus = 'idle' | 'loading' | 'authenticated' | 'error';
export type AuthErrorCode =
  | 'tokenMissing'
  | 'tokenExpired'
  | 'tokenInvalid'
  | 'unauthorized'
  | 'serverError';

export interface AuthContextType {
  authStatus: AuthStatus;
  authError: AuthErrorCode | null;
  token: string | null;
  retryCount: number;                         // incremented to re-trigger useAuthBridge
  setLoading: () => void;
  setTokenValidated: (token: string) => void;
  setAuthError: (code: AuthErrorCode) => void;
  retry: () => void;
}
```

**Key invariants:**
- `token` in React state is only set via `setTokenValidated()` — never read from storage directly.
- `token` is also persisted to localStorage (`access_token` key) after each successful validation via `authBridgeService.saveToStorage(token)`.
- `retry()` increments `retryCount`, which `useAuthBridge` depends on — this re-registers the listeners and re-attempts validation with the pending token (or falls through to localStorage/JS bridge if no pending token).

## 3. Auth Bridge Service — Validation & Storage

### File: `src/app/core/auth/services/auth-bridge.service.ts`

```typescript
interface ValidateResult {
  success: true;
  userId: string;
}

async validate(token: string): Promise<ValidateResult> {
  // Local dev bypass — no backend call needed
  if (environment.isLocal) {
    return { success: true, userId: 'local-dev-user' };
  }

  // Real validation — POST /auth/validate with Bearer token
  const response = await this.http.post<ValidateResult>(
    ENDPOINT.auth.validate,
    { token },
    { headers: { Authorization: `Bearer ${token}` } },
  );
  return response.data;
}

// localStorage persistence (KEYS.ACCESS_TOKEN = 'access_token')
saveToStorage(token: string): void { setLS(KEYS.ACCESS_TOKEN, token); }
loadFromStorage(): string | null    { return getLS(KEYS.ACCESS_TOKEN); }
clearFromStorage(): void            { removeLS(KEYS.ACCESS_TOKEN); }
```

Error mapping from HTTP responses to `AuthErrorCode`:

| HTTP status | Body code | `AuthErrorCode` |
|---|---|---|
| 401 | any | `unauthorized` |
| 403 | `TOKEN_EXPIRED` | `tokenExpired` |
| 403 | `TOKEN_INVALID` | `tokenInvalid` |
| 5xx | any | `serverError` |
| network error | — | `serverError` |

This mapping is done in `AuthBridgeService.mapErrorToCode(error)` — called from `useAuthBridge`'s catch block: `setAuthError(authBridgeService.mapErrorToCode(error))`.

## 4. useAuthBridge Hook

### File: `src/app/core/auth/hooks/useAuthBridge.ts`

```typescript
const useAuthBridge = () => {
  const { retryCount, setLoading, setTokenValidated, setAuthError } = useContext(AuthContext);
  const tokenReceivedRef = useRef(false);
  const pendingTokenRef = useRef<string | null>(null);

  const handleValidate = async (token: string, fromStorage = false) => {
    pendingTokenRef.current = token;
    setLoading();
    try {
      await authBridgeService.validate(token);
      if (!environment.isLocal) {
        authBridgeService.saveToStorage(token); // persist for cross-URL navigation (not for local-dev-token)
      }
      setTokenValidated(token);
    } catch (error) {
      if (fromStorage) {
        authBridgeService.clearFromStorage(); // remove expired/invalid stored token
        pendingTokenRef.current = null;       // don't retry this token — fall through to JS bridge
      }
      setAuthError(mapErrorToCode(error));
    }
  };

  useEffect(() => {
    tokenReceivedRef.current = false; // reset on retry

    // 1. URL param — highest priority, overwrites storage
    const urlToken = authBridgeService.extractFromUrlParam();
    if (urlToken) {
      tokenReceivedRef.current = true;
      handleValidate(urlToken);
      return;
    }

    // 2. Retry path — re-validate previously received token (skip if storage token already failed)
    if (pendingTokenRef.current) {
      tokenReceivedRef.current = true;
      handleValidate(pendingTokenRef.current);
      return;
    }

    // 3. localStorage — for subsequent WebView page loads without URL param
    const storedToken = authBridgeService.loadFromStorage();
    if (storedToken) {
      tokenReceivedRef.current = true;
      handleValidate(storedToken, true);
      return;
    }

    // 4. JS bridge — wait for mobile app to push token
    const handleMessage = (event: MessageEvent) => {
      if (tokenReceivedRef.current) return;
      const bridgeToken = authBridgeService.extractFromBridgeMessage(event);
      if (bridgeToken) {
        tokenReceivedRef.current = true;
        handleValidate(bridgeToken);
      }
    };
    window.addEventListener('message', handleMessage);

    // 5. Timeout — if nothing arrives within 5s, show tokenMissing
    const timeout = setTimeout(() => {
      if (!tokenReceivedRef.current) {
        setAuthError('tokenMissing');
      }
    }, 5000);

    return () => {
      window.removeEventListener('message', handleMessage);
      clearTimeout(timeout);
    };
  }, [retryCount]);
};
```

On `retry()` from context: `retryCount` increments → effect re-runs → `tokenReceivedRef` resets → bridge listener re-registers → `pendingTokenRef` token is re-submitted if still held.

For `serverError` retry: `pendingTokenRef.current` still holds the original token. On re-render, `useEffect` re-runs and immediately calls `handleValidate(pendingTokenRef.current)` since `tokenReceivedRef` resets to `false`.

## 5. AuthGate Container

### File: `src/app/core/auth/containers/AuthGate.tsx`

```tsx
const AuthGate = ({ children }: { children: ReactNode }) => {
  useAuthBridge(); // registers all listeners and drives context

  const { authStatus, authError, retry } = useContext(AuthContext);

  if (authStatus === 'idle' || authStatus === 'loading') {
    return <AuthLoadingScreen />;
  }

  if (authStatus === 'error' && authError) {
    return <AuthErrorScreen errorCode={authError} onRetry={retry} />;
  }

  return <>{children}</>;
};
```

`AuthLoadingScreen` — inline component or separate file — renders a full-screen spinner with Japanese aesthetic (warm background, centered spinner, no text).

```tsx
  errorCode: AuthErrorCode;
  onRetry?: () => void;

const AuthErrorScreen = ({ errorCode, onRetry }: AuthErrorScreenProps) => {
  const { t } = useTranslation('auth');
  return (
    <div className="auth-error-screen">
      <p className="auth-error-screen-title">{t(`${errorCode}.title`)}</p>
      <p className="auth-error-screen-body">{t(`${errorCode}.body`)}</p>
      {errorCode === 'serverError' && onRetry && (
        <button className="auth-error-screen-retry" onClick={onRetry}>
          {t('retry')}
        </button>
      )}
    </div>
  );
};
```

```typescript
  const { authStatus } = useContext(AuthContext);

    return <Navigate to="/" replace />;

  return <>{element}</>;
```

## 11. Acceptance Criteria Mapping

| AC | How it's met |
|---|---|
| AC-301 | `setTokenValidated()` → `authStatus = 'authenticated'` → `AuthGate` renders children |
| AC-302 | 403 + `TOKEN_EXPIRED` → `setAuthError('tokenExpired')` → `AuthErrorScreen` renders |
| AC-303 | 401 → `setAuthError('unauthorized')` → `AuthErrorScreen` renders |
| AC-304 | 500/503 → `setAuthError('serverError')` → `AuthErrorScreen` with retry button |
| AC-305 | 5s timeout with no token → `setAuthError('tokenMissing')` |
| AC-306 | `onRetry` calls `retry()` → `retryCount++` → `useAuthBridge` re-runs → re-validates |
| AC-307 | Token only in React state and localStorage; `AuthErrorScreen` renders only i18n strings |
| AC-308 | `authBridgeService.loadFromStorage()` picks up token on subsequent page load; re-validated before access granted |
| AC-309 | `fromStorage=true` path in `handleValidate` clears localStorage and nulls `pendingTokenRef` on failure |
