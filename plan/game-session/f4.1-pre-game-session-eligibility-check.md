## Architecture

Eligibility check is a gate that runs after E1 (auth) and before the game board renders. It is implemented as a hook + guard in `GameShell`, not as a route guard, because the check needs the in-memory auth token from `AuthContext`.

```
GameShell
  └─ useEligibilityCheck()          ← F4.1 gate
       └─ GameService.checkEligibility(token)
            └─ GET /game/eligibility
  ├─ status === 'loading'   → <Spinner />
  ├─ status === 'error'     → <GameSessionCheckError onRetry />
  ├─ status === 'ineligible'→ <PlayLimitScreen nextPlayAt />  (F4.2)
  └─ status === 'eligible'  → <GameContent />
       └─ useGameSession()
```

`GameContent` is a sub-component of `GameShell` (same file, not exported). It owns `useGameSession` so the game hook only runs when eligibility is confirmed — satisfying SEC-412 (game board not accessible without eligible response).

## useEligibilityCheck

```typescript
type EligibilityStatus = 'loading' | 'eligible' | 'ineligible' | 'error';
// status: 'loading' on mount + on retry
// status: 'eligible'   → backend { eligible: true }
// status: 'ineligible' → backend { eligible: false, nextPlayAt? }
// status: 'error'      → network/server error (not 401 — that's handled by auth)
```

Runs `check()` on mount via `useEffect`. `retry` is the same `check` callback, exposed for the error screen.
