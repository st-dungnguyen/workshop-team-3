# Feature PRD: F3.2 — Coupon Delivery via AppLink

## 1. Feature Name

**Coupon Delivery via AppLink** — Navigates the player to either the coupon detail screen or the takeout ordering screen in the native app via AppLink, completing the reward flow based on which CTA the player chose.

## 2. Epic

- **Parent Epic:** [E3 — Reward/Coupon](./_epic-E3-reward-coupon.md)
- **Priority:** P0 — Critical

## 3. Purpose & Scope

After F3.1 successfully issues a coupon and returns a `couponId`, the WebView's final responsibility is to navigate the player to the appropriate native screen via AppLink. The destination depends on which CTA the player tapped on the win result screen (F2.3):

- **"Claim Coupon"** → segment coupon detail screen: `https://www.skylark.co.jp/app/coupon/segment?id={couponId}`
- **"Use Now"** → takeout ordering screen with coupon pre-applied: `https://www.skylark.co.jp/app/takeout?coupon_id={couponId}`

The WebView's role in the reward flow ends at this navigation. Coupon display, order placement, and subsequent UI are handled entirely by the native app.

**Intended Audience:** Engineering team.

**Assumptions:**
- The `couponId` is received from F3.1 and held in memory. F3.2 does not fetch or issue the coupon itself.
- The CTA intent (`claimCoupon` or `useNow`) is passed from the result screen (F2.3) through F3.1 to F3.2, so F3.2 knows which AppLink to fire.
- Both iOS and Android handle both AppLink URLs correctly (v8.0.7+ for `/app/takeout`).
- The same `couponId` value returned by F3.1 is used for both AppLink paths. **Note:** The compatibility of a segment coupon ID with the `/app/takeout?coupon_id=` parameter must be confirmed with the backend team before implementation — these may be the same ID or require a separate field in the win-record response.
- The coupon type is always **segment** — the "Claim Coupon" path must use `/app/coupon/segment`, never `/app/coupon/detail`.
- `sklgusto://close` is not used in this flow. The WebView navigates away via AppLink.

## 4. User Personas

| Persona | Description |
|---|---|
| **PLAYER ("Claim Coupon")** | Wants to save the coupon for later; expects to land on the coupon detail screen in the native app |
| **PLAYER ("Use Now")** | Wants to use the coupon immediately; expects to land on the takeout screen with the coupon already applied |
| **HOST** | The native iOS or Android app; intercepts the AppLink URL and opens the appropriate native screen |

## 5. User Stories

- As a **PLAYER who tapped "Claim Coupon"**, I want to be taken directly to my coupon detail so that I can view it, save it, and use it later.
- As a **PLAYER who tapped "Use Now"**, I want to be taken directly to the takeout ordering screen with my coupon applied so that I can place my order immediately without extra steps.
- As a **PLAYER**, I want the transition from the win result to the native screen to be seamless so that winning feels instantly rewarding.

## 6. Requirements

### Functional Requirements

- **REQ-321**: When the `GameSession` transitions to `rewarded` and the CTA intent is `claimCoupon`, the system shall navigate to `https://www.skylark.co.jp/app/coupon/segment?id={couponId}` using `window.location.href`.
- **REQ-322**: When the `GameSession` transitions to `rewarded` and the CTA intent is `useNow`, the system shall navigate to `https://www.skylark.co.jp/app/takeout?coupon_id={couponId}` using `window.location.href`.
- **REQ-323**: For the "Claim Coupon" path, the AppLink must use `/app/coupon/segment` — not `/app/coupon/detail` or any other coupon path.
- **REQ-324**: Both AppLink URLs must include the correct query parameter (`id` for segment coupon detail; `coupon_id` for takeout) set to the exact `couponId` value returned by F3.1, URL-encoded.
- **REQ-325**: Navigation shall fire immediately after F3.1 succeeds — no additional player action is required between the `rewarded` transition and the AppLink firing.
- **REQ-326**: If the `couponId` is absent or empty when this feature is triggered, the system shall not navigate and shall display a `reward.claimError` state with a retry option.
- **REQ-327**: If the CTA intent is absent or unrecognized, the system shall default to the `claimCoupon` path (navigate to coupon detail).

### Security Requirements

- **SEC-321**: The `couponId` used to construct either AppLink URL shall come from the in-memory value received from F3.1 only. It must not be read from localStorage, sessionStorage, URL parameters, or any other external source.
- **SEC-322**: The `couponId` value must be URL-encoded before insertion into the query parameter.

### Constraints

- **CON-321**: Both AppLink navigations are one-way transitions — once `window.location.href` is set, the WebView context is replaced or backgrounded by the native app. There is no "back" navigation to the WebView.
- **CON-322**: The WebView must not display the coupon's full details (name, discount amount, expiry) itself. Coupon display is the native app's responsibility after AppLink navigation.
- **CON-323**: Neither AppLink must be triggered before the `GameSession` is in `rewarded` state. A failed or pending win-recording attempt must not trigger navigation.

### Guidelines

- **GUD-321**: Between the `GameSession` transitioning to `rewarded` and the AppLink firing, the system may briefly display a transition message (e.g., "クーポンを獲得しました！" / `reward.couponIssued`) — no more than 1–2 seconds — so the handoff feels intentional rather than abrupt.
- **GUD-322**: The transition message (if shown) should not differ based on which CTA was tapped — the message confirms the coupon was issued, not the destination.

## 7. Acceptance Criteria

- **AC-321**: Given the `GameSession` transitions to `rewarded` with a valid `couponId` and intent `claimCoupon`, then `window.location.href` is set to `https://www.skylark.co.jp/app/coupon/segment?id={couponId}`.
- **AC-322**: Given the `GameSession` transitions to `rewarded` with a valid `couponId` and intent `useNow`, then `window.location.href` is set to `https://www.skylark.co.jp/app/takeout?coupon_id={couponId}`.
- **AC-323**: Given the "Claim Coupon" AppLink is triggered, then the URL path is `/app/coupon/segment` — not `/app/coupon/detail`.
- **AC-324**: Given the "Use Now" AppLink is triggered, then the URL path is `/app/takeout` with `coupon_id` parameter — not `/app/coupon/segment`.
- **AC-325**: Given both AppLinks, then the coupon ID in the query parameter exactly matches the `couponId` from F3.1 (URL-encoded).
- **AC-326**: Given F3.1 returns a `couponId` of `""` (empty string) or null, then no AppLink navigation fires and `reward.claimError` is shown.
- **AC-327**: Given the CTA intent is missing or unrecognized, then the system navigates via the `claimCoupon` path (coupon detail).
- **AC-328**: Given a `couponId` is used to construct either AppLink, then the `couponId` value was never read from localStorage, sessionStorage, or any URL parameter.

## 8. Test & Validation Criteria

**Test Perspectives:**

- **Happy path — "Claim Coupon":** F3.1 returns `couponId` + intent `claimCoupon` → AppLink fires to `/app/coupon/segment?id={couponId}` → native coupon detail screen opens.
- **Happy path — "Use Now":** F3.1 returns `couponId` + intent `useNow` → AppLink fires to `/app/takeout?coupon_id={couponId}` → native takeout screen opens with coupon applied.
- **Correct coupon type (Claim Coupon):** URL uses `/app/coupon/segment`, not `/app/coupon/detail`.
- **Correct path (Use Now):** URL uses `/app/takeout`, not `/app/coupon/segment`.
- **ID accuracy — both paths:** Query param matches `couponId` from F3.1 exactly — no truncation or transformation.
- **URL encoding:** `couponId` with special characters (hyphens, alphanumerics) → correct URL encoding in both AppLink variants.
- **Guard — empty couponId:** F3.1 returns empty/null `couponId` → `reward.claimError` shown, no AppLink fired regardless of intent.
- **Default intent fallback:** Missing or unrecognized intent → navigates via "Claim Coupon" path.
- **No extra tap:** From F3.1 success to AppLink navigation — no player interaction required.
- **Security — source of couponId:** After navigation, inspect localStorage/sessionStorage → `couponId` must be absent from both.
- **iOS — "Claim Coupon":** Real iOS device → native coupon detail screen opens.
- **iOS — "Use Now":** Real iOS device → native takeout screen opens with coupon pre-applied.
- **Android — both paths:** Same verification on Android.
- **Back navigation:** After native app screen opens, player cannot navigate back to the WebView game.
- **Locale:** Transition message (if shown) displays in `ja` by default; switches to `en` when locale changes.

## 9. Out of Scope

- Displaying coupon details (name, discount, expiry) within the WebView — the native app owns this.
- Coupon redemption, validation, or expiry — native app and backend concern.
- What the native app does after intercepting either AppLink — HOST responsibility.
- Handling the case where the native app is not installed or the AppLink is not intercepted — out of WebView control.
- Navigating to a fallback web page if AppLink interception fails.
- `sklgusto://close` integration — not yet merged as of 2026-08.
- Determining whether the segment `couponId` is accepted by `/app/takeout?coupon_id=` — this is a backend API contract question to be resolved before implementation.
