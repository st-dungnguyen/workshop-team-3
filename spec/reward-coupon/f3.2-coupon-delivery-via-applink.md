# Feature PRD: F3.2 — Coupon Delivery via AppLink

## 1. Feature Name

**Coupon Delivery via AppLink** — Navigates the player to either the specific won coupon detail screen or the coupon list screen in the native app via AppLink, based on which CTA the player taps on the win result screen.

## 2. Epic

- **Parent Epic:** [E3 — Reward/Coupon](./_epic-E3-reward-coupon.md)
- **Priority:** P0 — Critical

## 3. Purpose & Scope

After the win result screen appears, the player can tap one of two CTAs to access their coupon in the native app:

- **"Use Coupon"** (`result.useCoupon`) — takes the player directly to the specific won coupon detail screen, ready to be used: `https://www.skylark.co.jp/app/coupon/segment?id={couponId}`
- **"My Coupon"** (`result.myCoupon`) — takes the player to the native app's coupon list screen to view all their coupons: `https://www.skylark.co.jp/app/coupon`

Navigation fires immediately on CTA tap. There is no API call or loading state between the tap and the AppLink firing. The `couponId` used for the "Use Coupon" path is the value received from the `play()` response (F2.2) and stored in memory — it does not depend on the background claim (F3.1) completing.

The WebView's role in the reward flow ends at this navigation.

**Intended Audience:** Engineering team.

**Assumptions:**
- The `couponId` is received from the `play()` response and held in memory (F3.1). F3.2 does not fetch or issue the coupon itself.
- The background claim (F3.1) fires independently of these CTAs. F3.2 does not wait for the claim to complete before enabling navigation.
- Both iOS and Android handle the AppLink URLs correctly.
- The coupon type is always **segment** — the "Use Coupon" path must use `/app/coupon/segment`, not `/app/coupon/detail`.
- `sklgusto://close` is not used in this flow.

## 4. User Personas

| Persona | Description |
|---|---|
| **PLAYER ("Use Coupon")** | Wants to use the specific won coupon immediately; expects to land on the coupon detail screen in the native app |
| **PLAYER ("My Coupon")** | Wants to view all their coupons; expects to land on the native app's coupon list screen |
| **HOST** | The native iOS or Android app; intercepts the AppLink URL and opens the appropriate native screen |

## 5. User Stories

- As a **PLAYER who tapped "Use Coupon"**, I want to be taken directly to my won coupon detail so that I can use it immediately.
- As a **PLAYER who tapped "My Coupon"**, I want to see all my coupons so that I can decide when and how to use this one.
- As a **PLAYER**, I want both CTAs to respond immediately on tap — no loading, no wait — so that winning feels instantly rewarding.

## 6. Requirements

### Functional Requirements

- **REQ-321**: When the player taps "Use Coupon" on the win result screen, the system shall navigate to `https://www.skylark.co.jp/app/coupon/segment?id={couponId}` using `window.location.href`, where `{couponId}` is the URL-encoded value received from the `play()` response.
- **REQ-322**: When the player taps "My Coupon" on the win result screen, the system shall navigate to `https://www.skylark.co.jp/app/coupon` using `window.location.href`.
- **REQ-323**: For the "Use Coupon" path, the AppLink must use `/app/coupon/segment` — not `/app/coupon/detail` or any other coupon path.
- **REQ-324**: The "Use Coupon" AppLink must include the `id` query parameter set to the exact `couponId` value from the `play()` response, URL-encoded.
- **REQ-325**: Navigation shall fire immediately on CTA tap — no intermediate API call, no loading state.
- **REQ-326**: If `couponId` is absent or empty when "Use Coupon" is tapped, the system shall not navigate and shall take no action (the button handler exits silently).
- **REQ-327**: "My Coupon" navigation does not require a `couponId` and shall always be available when the player is on the win result screen.

### Security Requirements

- **SEC-321**: The `couponId` used to construct the "Use Coupon" AppLink URL shall come from the in-memory value received from the `play()` response only. It must not be read from localStorage, sessionStorage, URL parameters, or any other external source.
- **SEC-322**: The `couponId` value must be URL-encoded before insertion into the query parameter.

### Constraints

- **CON-321**: Both AppLink navigations are one-way transitions — once `window.location.href` is set, the WebView is replaced or backgrounded by the native app. There is no "back" navigation to the WebView.
- **CON-322**: Neither CTA shall trigger an API call. Navigation is direct — no middleware through E3.
- **CON-323**: Neither AppLink shall fire before the win result screen is displayed and the player has an active `GameSession` with `outcome: win`.

### Guidelines

- **GUD-321**: "Use Coupon" shall be the visually primary CTA (filled, `btn-primary`) and "My Coupon" the secondary CTA (outlined, `btn-secondary`) — the business goal is to convert the coupon to an order immediately.
- **GUD-322**: Both CTAs must meet a minimum touch target height of 44px.

## 7. Acceptance Criteria

- **AC-321**: Given the player is on the win result screen with a valid `couponId`, when they tap "Use Coupon", then `window.location.href` is set to `https://www.skylark.co.jp/app/coupon/segment?id={couponId}` — no API call precedes this navigation.
- **AC-322**: Given the player taps "My Coupon", then `window.location.href` is set to `https://www.skylark.co.jp/app/coupon` — no API call precedes this navigation.
- **AC-323**: Given the "Use Coupon" AppLink is triggered, then the URL path is `/app/coupon/segment` — not `/app/coupon/detail`.
- **AC-324**: Given the "Use Coupon" AppLink is triggered, then the `id` query parameter exactly matches the `couponId` from the `play()` response (URL-encoded).
- **AC-325**: Given `couponId` is absent or empty, when the player taps "Use Coupon", then no navigation fires.
- **AC-326**: Given the `couponId` is used for the "Use Coupon" AppLink, then it was never read from localStorage, sessionStorage, or any URL parameter.
- **AC-327**: Given the background claim (F3.1) is still in flight, when the player taps either CTA, then navigation fires immediately — the CTAs are not blocked by the in-flight claim.

## 8. Test & Validation Criteria

**Test Perspectives:**

- **Happy path — "Use Coupon":** Win screen shown with valid `couponId` → player taps "Use Coupon" → `window.location.href` set to `/app/coupon/segment?id={couponId}` → native coupon detail screen opens.
- **Happy path — "My Coupon":** Win screen shown → player taps "My Coupon" → `window.location.href` set to `/app/coupon` → native coupon list opens.
- **Correct coupon type:** URL uses `/app/coupon/segment`, not `/app/coupon/detail`.
- **URL encoding:** `couponId` with special characters → correctly URL-encoded in AppLink.
- **No API call:** Network inspector shows no request fires when either CTA is tapped.
- **Claim in flight:** Background claim still pending when CTA is tapped → navigation fires anyway (CTAs not blocked by claim).
- **Guard — empty couponId:** `play()` returns empty/null `couponId` → "Use Coupon" tapped → no navigation, no error thrown.
- **"My Coupon" always available:** "My Coupon" navigates correctly even if `couponId` is absent (it doesn't need one).
- **Security — source of couponId:** After navigation, localStorage/sessionStorage do not contain the `couponId`.
- **iOS — "Use Coupon":** Real iOS device → native coupon detail screen opens.
- **iOS — "My Coupon":** Real iOS device → native coupon list opens.
- **Android — both paths:** Same verification on Android.
- **Touch targets:** Both CTAs meet 44px minimum height.
- **Locale — "Use Coupon" label:** `ja` shows "クーポンを使う"; `en` shows "Use Coupon".
- **Locale — "My Coupon" label:** `ja` shows "クーポンを確認する"; `en` shows "My Coupon".

## 9. Out of Scope

- Displaying coupon details (name, discount, expiry) within the WebView beyond the preview from `play()` — the native app owns this after AppLink navigation.
- A "Use Now" → takeout ordering screen path — this has been superseded by the "Use Coupon" → coupon detail path.
- Coupon redemption, validation, or expiry — native app and backend concern.
- What the native app does after intercepting either AppLink — HOST responsibility.
- Handling the case where the native app is not installed or the AppLink is not intercepted.
- `sklgusto://close` integration — not yet merged as of 2026-08.
