# Feature PRD: F2.4 — Daily Streak System

## 1. Feature Name

**Daily Streak System** — Tracks a player's consecutive daily plays in the Scratch Card variant, displays their progress on a 7-day streak bar, and awards a special bonus coupon upon completing a 7-day streak.

## 2. Epic

- **Parent Epic:** [E2 — Game Core](./_epic-E2-game-core.md)
- **Priority:** P1 — High

## 3. Purpose & Scope

The Daily Streak System encourages repeated daily engagement by rewarding players who play on consecutive days. It is exclusive to the **Scratch Card variant** — the Flip Card variant does not display a streak bar.

The streak works as follows:
1. Each day the player plays, that day is marked as complete on the 7-day tracker.
2. If the player plays on 7 consecutive days, they receive a special bonus coupon in addition to their regular game coupon.
3. If the player misses a day, the streak resets to day 1, and a streak-reset screen is shown the next time they open the WebView.
4. Day 7 of the streak is always shown as a special "bonus" slot (🎁 icon, gold color) to make the reward visible throughout the challenge.

The streak data (current count, days completed, reset status) is authoritative from the backend — the frontend displays it, it does not compute it.

**Intended Audience:** Engineering team.

**Assumptions:**
- Streak data is returned by the backend as part of the eligibility check response (F4.1) or a dedicated session-info endpoint.
- The frontend never computes whether a day "counts" or whether the streak resets — it only renders what the backend provides.
- A session counts toward the streak only after it is completed (i.e., the player plays, regardless of win or lose). Viewing the game screen without playing does not count.
- A streak reset occurs when a calendar day passes without a completed session. The reset notification is shown once — on the player's next WebView open after the missed day.
- The 7-day bonus coupon is issued via the same win-recording flow (F3.1) triggered from the bonus result screen, not as a separate API call.
- Streak is only active when the Scratch Card variant is configured (F2.1). The Flip Card variant does not show or track streaks.

## 4. User Personas

| Persona | Description |
|---|---|
| **PLAYER** | Plays daily to build their streak toward the 7-day bonus; sees their progress on the streak bar each visit |
| **SYSTEM** | Tracks consecutive play days server-side; returns streak state with each session-info response; determines whether a streak bonus is earned |

## 5. User Stories

- As a **PLAYER**, I want to see how many consecutive days I've played so that I feel motivated to maintain my streak toward the 7-day bonus.
- As a **PLAYER**, I want to know which day of the week earns me the special bonus so that I can plan to play on that day.
- As a **PLAYER** who completes a 7-day streak, I want to receive a special bonus coupon that is more valuable than the regular coupon so that my effort feels rewarded.
- As a **PLAYER** who missed a day, I want a clear, encouraging message explaining that my streak has reset so that I understand what happened and am motivated to start again.
- As a **PLAYER**, I want to see my streak updated on the result screen after I play so that I know my play was counted toward the challenge.

## 6. Requirements

### Functional Requirements

**Streak Bar Display**

- **REQ-241**: When the Scratch Card variant is active, the system shall display a streak bar on the main game screen showing a 7-slot tracker labeled by day of the week.
- **REQ-242**: Each slot in the streak bar shall be rendered in one of four visual states: `done` (played), `today` (current day, not yet played), `upcoming` (future day, not yet played), or `bonus` (day 7 special slot). The `bonus` slot on day 7 is visually distinct (gold color, gift icon) regardless of streak status.
- **REQ-243**: The streak bar shall display the current consecutive day count alongside a localized label (e.g., "🔥 3日連続" / `streak.consecutiveDays`).
- **REQ-244**: The streak bar shall be visible both on the main game screen (before playing) and on the result screen (after playing), with the result screen showing the updated count.

**7-Day Streak Bonus**

- **REQ-251**: When the backend confirms the player has completed a 7-day streak (all 7 consecutive slots `done`), the system shall navigate to the **7-Day Streak Bonus screen** instead of the standard result screen.
- **REQ-252**: The 7-Day Streak Bonus screen shall display: a celebratory header, all 7 streak slots shown as `done`, a visual representation of the bonus coupon (e.g., 1,000円OFF), and a CTA to claim the bonus coupon.
- **REQ-253**: The bonus coupon CTA shall trigger the same win-recording flow as a standard win (F3.1), with a session-type indicator in the request payload that tells the backend this is a streak-bonus claim. The `couponId` returned is the streak bonus coupon.
- **REQ-254**: After the streak bonus coupon is successfully issued, the system shall navigate to AppLink delivery (F3.2) with the bonus `couponId`.
- **REQ-255**: After a 7-day streak is completed and the bonus is claimed, the streak resets to 0 and a new 7-day challenge begins on the player's next visit.

**Streak Reset**

- **REQ-261**: When the backend indicates the player's streak has been reset (due to a missed day), the system shall display a **Streak Reset screen** before the game board.
- **REQ-262**: The Streak Reset screen shall: explain that the streak was reset (localized, warm tone — not punishing), show the streak bar reset to day 1 (`today` slot active), and display a CTA to start today's play.
- **REQ-263**: Tapping the "Start today's play" CTA on the Streak Reset screen shall navigate the player to the main game board.
- **REQ-264**: The Streak Reset screen shall be shown at most once per WebView session — not again if the player navigates within the same session.

### Localization

- **REQ-271**: All streak-related strings must be available in `ja` and `en` under the `streak.json` i18n namespace.

### Constraints

- **CON-241**: The streak bar is exclusive to the Scratch Card variant. It must not appear when Flip Card is the active variant.
- **CON-242**: The frontend must not compute or override streak state. If the backend does not return streak data, the streak bar must not be shown.
- **CON-243**: The 7-day bonus coupon claim must flow through F3.1 and F3.2 — no separate coupon issuance path may be introduced for streak bonuses.

### Guidelines

- **GUD-241**: The streak bar design should make the day-7 bonus slot visually unmistakable (gold/highlight color) so players always know what they are building toward.
- **GUD-242**: The streak reset message should be warm and encouraging — similar in tone to the lose result screen. Avoid phrasing that sounds like a penalty (e.g., "違反", "失効"). Preferred tone: "また1日目から頑張りましょう！" (`streak.resetEncouragement`).
- **GUD-243**: The 7-day bonus screen should be clearly more celebratory than the standard win screen — use confetti animation, a larger coupon visual, and a trophy or star motif.

## 7. Acceptance Criteria

**Streak Bar**

- **AC-241**: Given the Scratch Card variant is active and the player has a 3-day streak, when the main game screen loads, then the streak bar shows 3 `done` slots, 1 `today` slot, 2 `upcoming` slots, and 1 `bonus` slot on day 7.
- **AC-242**: Given the player wins (any tier), when the result screen appears, then the streak bar shows the same data with the player's current day now marked `done` and the streak count incremented by 1.
- **AC-243**: Given the Flip Card variant is active, when the game screen loads, then no streak bar is visible.
- **AC-244**: Given the backend does not return streak data (no streak field in response), then the streak bar is not rendered (no broken placeholder).

**7-Day Bonus**

- **AC-251**: Given the player completes their 7th consecutive day, when the backend confirms the 7-day streak, then the 7-Day Streak Bonus screen appears instead of the standard result screen.
- **AC-252**: Given the 7-Day Bonus screen is shown, when the player taps "Claim Bonus Coupon", then a win-recording request with streak-bonus type is sent, and on success, AppLink delivery to the bonus coupon detail is triggered.
- **AC-253**: Given the bonus claim fails (backend 500/503), then a retry option is shown and the player is not left without a path to claim the bonus.

**Streak Reset**

- **AC-261**: Given the player missed yesterday's play, when they open the WebView, then the Streak Reset screen appears before the game board.
- **AC-262**: Given the Streak Reset screen is shown, when the player taps "Start today's play", then they are taken to the main game board with the streak reset to day 1.
- **AC-263**: Given the Streak Reset screen has been shown once in this session, when the player navigates back to the game screen, then the Streak Reset screen does not appear again.

## 8. Test & Validation Criteria

**Test Perspectives:**

- **Day 1 streak:** Player opens for the first time or after reset → streak bar shows 1 `today` slot, 5 `upcoming`, 1 `bonus` (day 7).
- **Day 3 streak:** 3 `done` slots, 1 `today`, 2 `upcoming`, 1 `bonus`.
- **Day 6 streak:** 6 `done` slots, 1 `bonus` (today with gold), streak count shows "6日連続".
- **Day 7 bonus triggered:** Backend returns streak-complete → 7-Day Bonus screen shown, not standard result screen.
- **Bonus claim — success:** Bonus screen → CTA tapped → backend returns bonus `couponId` → AppLink navigation.
- **Bonus claim — failure:** Backend 500 → retry shown → win confirmation remains visible.
- **Streak reset notification:** Player missed a day → backend returns reset status → Streak Reset screen shown.
- **Reset notification shown once:** Streak Reset screen shown → player navigates within session → Streak Reset screen does not reappear.
- **Flip Card — no streak bar:** Flip Card variant active → no streak bar visible, no streak API call.
- **Missing streak data:** Backend returns no streak field → streak bar absent, no JS error.
- **Locale (ja):** Streak count, day labels, reset message all in Japanese.
- **Locale (en):** Same strings in English after locale switch.
- **Confetti on bonus:** 7-Day Bonus screen → confetti animation plays.
- **App backgrounded mid-streak claim:** Player backgrounds app while bonus claim in flight → on resume, loading state shown, no duplicate request.

## 9. Out of Scope

- Computing streak eligibility client-side — backend is authoritative.
- Showing full play history (dates of every session played) — this is a future enhancement.
- Streak mechanics for the Flip Card variant — the Flip Card does not have a daily streak system.
- Push notifications reminding the player to maintain their streak — native app concern.
- Partial-day grace periods or streak recovery mechanics — the backend determines these rules; the frontend only renders the result.
- Leaderboards or comparison with other players' streaks.
- The specific coupon value for the 7-day bonus — that is set in campaign configuration (F2.1), not hardcoded in the frontend.
